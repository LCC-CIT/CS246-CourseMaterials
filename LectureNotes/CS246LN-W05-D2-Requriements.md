## Gathering Software Requirements

Your team will gather software requirements in same way a small software development company would do it. You will follow this process:

### This week: Interview and Requirements Doc

- Interview the client.
  - Look at the fictitious example interveiws (the case studies) from the first week of class to get ideas about how to conduct an interview.
  - Take notes and / or record the interview (with the client's permission).

- Write a high-level requirements document.
  - This will be like the one you wrote at the beginning of the term.
  - If questions come up while writing this document (and they probably will), do a second interview with the client.


### Next Two Weeks: UX Diagrams and User Stories

- Create UX diagrams, like you did earlier this term
  - Test the UX design with your client
  - Review the UX design based on feedback.
  - Revise your requirements document based on things you learned while making the UX diagrams.

- Create a Jira project and add epics and user stories.



## How this in Done in a Larger Company

In a mid to large sized company, there might be seaprate roles for the people involved in the process of starting with business requiremets and untimately producing a software system or application that meets those requirements.

A software project will often be started when a ***Business Analyst*** develops a *Business Case* and/or *Business Requirements*. 

A ***Systems Analyst*** will then develop *System or Software Requirements Specification* (SRS) using the Business Requirements as a starting point. 

***Software Architects/Engineers*** will then design the system and/or software based on the SRS.

***Software Developers*** will implement the software.

This process will often be followed even when the development team is using an Agile approach.

In small or mid-sized companies all of these functions might be done by software develpers or engineers.

### Business Requirements

*Business requirements* are the business problems (aka needs) that a software product will be a solution for.  They include goals and objectives, stakeholder needs, functional and non-functional requirements, constraints, and use cases. 

### Software Requirements

*Software requirements* refer to detailed descriptions of the functionalities, features, and constraints of a software system. They encompass both *functional requirements*, which specify what the software should do (e.g., tasks, services, and functions), and *non-functional requirements*, which outline the system's quality attributes and performance criteria (e.g., security, reliability, scalability, and usability). These requirements are based on the *business requirements* for this software solution.

## Requirements Documentation in This Course

In this course you are writing a requirements document that merges business requirements and software requirements. You are further documenting the requirements with user stories. You will also be making UX diagrams to further refine the software requireemnts as well as to start the design of the software solution.
